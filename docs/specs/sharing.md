# 文書の共有

通常のプレビューはローカルHTMLを生成したあと、Cloudflare Quick Tunnelによる共有を試みます。
`--no-share` は完全にオフラインで動作します。共有に失敗してもローカルHTMLは利用できます。
URLを知る人が文書を閲覧できます。認証、常設公開、自動監視は提供しません。

<!-- @code src/share.rs#Snapshot -->
## スナップショット

共有するHTMLのバイト列と、描画時に読み込んだ画像などの許可リストをまとめて扱います。
更新時には全体を一括で交換するため、各HTTP応答は更新前か更新後のどちらか一方を参照します。
管理メッセージの上限は128MiBです。初期・更新とも送信前に上限を確認します。
バイト列はJSONの数値列で送ります。初期保存と更新には同じシリアライズ済みスナップショットを利用します。
Markdown原文やリンク先文書、任意のローカルファイルは配信しません。

<!-- @code src/share.rs#start_or_update -->
## 共有の起動と更新

文書のcanonical絶対パスとCLIが選ぶキャッシュルートを使って、文書単位に共有します。
同じ文書の生存中のセッションではURLを再利用し、HTMLと画像を一括更新します。
スマートフォンの表示には手動の再読み込みが必要です。
起動・管理待機の期限は15秒です。cloudflared未導入、URL取得のタイムアウトなどは共有失敗になります。
呼び出し側は共有失敗をローカル表示へのフォールバックとして扱います。
更新IPCの接続・送信・受信・解析は、呼び出し全体の15秒の期限内で行います。
更新に失敗したときは「既存の共有は更新前の内容で継続している可能性があります」と伝えます。
応答を受け取れなかった場合、更新自体が反映済みの可能性もあるため、停止したとは扱いません。

共有は内部引数 `--share-daemon <session_dir>` で自分の実行ファイルを再起動します。
標準入力は起動確認専用パイプとし、確認後は利用しません。
標準出力と標準エラーは専用ログに接続して端末から切り離します。
親は公開URLを確認した後、パイプに1バイトの `R` を送り、パイプを閉じて起動を確定します。
確認前の親死亡やCtrl+CによるパイプEOF、不正な確認バイト、読み取り失敗ではデーモンを終了します。
確認後のEOFはエラー扱いしません。内部引数だけの手動起動で標準入力がEOFになった場合も停止します。
公開URLはcloudflaredの標準エラーにある `https://<名前>.trycloudflare.com` のみを受け入れます。
HTTPのバインドとルートの応答を確認してからURLを返します。

## 共有の停止

指定した文書の共有をUnix管理ソケット経由で停止し、生存ロックの解放を待ちます。
停止済みの場合も成功します。生存中のデーモンに接続できない場合はエラーを返し、
保存されたPIDを使って別のプロセスを終了しません。

<!-- @code src/share.rs#stop_all -->
## 全共有の停止

CLIが選んだキャッシュルートに属する共有を停止します。
他のキャッシュルートの共有には作用しません。全体の管理待機期限は15秒です。
1件の失敗で中断せず、すべてのセッションの停止を試行して最後にエラーをまとめて返します。
期限を使い切った場合も残りのセッションを確認しますが、待機期限は延長しません。

## 共有デーモン

HTTPは `127.0.0.1:0` のみにバインドします。
GETの `/` と `/index.html` はHTMLを、その他のパスはスナップショットの許可リストとの完全一致のみを配信します。
クエリーは配信ファイルの選択に影響しません。パスのデコードやファイルシステムへの展開はしません。
許可していないパスは404、GET以外は405です。すべての応答に `Cache-Control: no-store` と
`X-Content-Type-Options: nosniff` を付けます。管理APIはHTTPに公開しません。
HTTP接続はaccept後に明示的にブロッキングへ戻し、読み書きのタイムアウトを設定します。
リクエストヘッダーの受信期限は1秒、応答全体の送信期限は30秒です。
スマホ回線で大きな画像を返す時間を確保します。30秒を超える送信は途中で終了します。
HTTPの同時処理は32接続までで、枠が空くまでは待ち行列に残します。
上限内のHTTP接続は並行処理し、管理による停止はHTTPの完了を待ちません。

Quick Tunnelは次の引数で起動します。

```text
cloudflared tunnel --no-autoupdate --url http://127.0.0.1:<port>
```

利用者の既存cloudflared設定を変更しません。
トンネルの異常終了、URL取得失敗、停止要求では子プロセスをkill/waitしてデーモンも終了します。
起動した親がタイムアウトしたときは、自分で生成したデーモンに終了を依頼し、必要なら専用プロセスグループを掃除します。
起動確認前に親のパイプが閉じた場合も通常の終了経路でトンネル子をkill/waitします。
外部からデーモンをSIGKILLした場合のトンネル子の回収は、OSをまたいでは保証できません。
古いPIDや再利用されたPIDのプロセスグループを推測してkillする復旧処理は行いません。

状態・スナップショット・ログはキャッシュルート配下の `sharing/<文書識別子>/` に保存します。
専用ディレクトリは0700、ファイルは0600です。管理ソケットは短いパスを確保するため、
本人所有の0700ディレクトリ `/tmp/miyaburu-share-<uid>/` に置き、ソケット自体も0600にします。
所有者とディレクトリ権限を検証し、不適切な既存ディレクトリは使用しません。
文書識別子とソケット名は、canonicalパスのOSバイト列に対する固定実装のFNV-1a u64を使います。
offsetは14695981039346656037、primeは1099511628211で、ツールチェーン更新によって変わりません。

文書単位の管理ロックで起動・更新・停止を直列化し、デーモンの生存ロックで二重起動を防ぎます。
生存ロックを取得できる場合だけ、古いソケットを削除して復旧します。
管理接続は接続・読み書きに期限を設け、途中まで送るクライアントでも待機を引き延ばせません。
デーモン側の管理受信・送信・解析も接続全体で15秒を上限とします。
PIDを状態ファイルに保存せず、古い状態やPIDの再利用を理由に別プロセスをkillしません。
診断ログはセッションディレクトリの `daemon.log` と `cloudflared.log` です。
